# 1. Introduction

This Software Design Document (SDD) describes the internal software architecture, component design, database interactions, workflows, and implementation details of DeepNote v0.1.

The purpose of this document is to provide a technical blueprint for developing the application while maintaining modularity, simplicity, and maintainability.

---

# 2. System Overview

DeepNote is an offline semantic note-taking application.

The application combines a traditional plain-text editor with AI-powered semantic search.

The system stores:

- Notes as TXT files (Source of Truth)
- Metadata and vector embeddings inside PostgreSQL using pgvector

Whenever a note is saved, the application checks whether its contents have changed using a SHA-256 hash. If the content has changed, semantic indexing is performed in a background SwingWorker so that the user interface remains responsive.

# 4. Architectural Style

DeepNote follows a layered architecture based on the MVC (Model-View-Controller) design pattern.

Layers include:

- Presentation Layer (Swing UI)
- Controller Layer
- Service Layer
- Data Access Layer (DAO)
- Database Layer
- File Storage Layer

This separation improves maintainability and makes the application easier to understand and extend.

Contains the application's business logic.

Responsibilities:

- Save notes
- Perform searches
- Generate embeddings
- Coordinate indexing

`SearchService` does not implement search logic directly. It delegates to a `Searcher` implementation:

```
SearchService

↓

Searcher (interface)

↓

VectorSearcher   TextSearcher
```

- `VectorSearcher` performs semantic search using embeddings and pgvector.
- `TextSearcher` performs keyword search as a fallback.
- `SearchService` selects between them at runtime depending on whether Ollama/semantic search is available.

# 8. Save & Index Workflow

```
User

↓

Ctrl + S / Save Button

↓

Write TXT File

↓

Compute currentSavedHash

↓

Same as indexedContentHash?

↓

Yes

↓

Skip Everything

↓

No

↓

Save TXT

↓

Worker Already Running?

↓

No

↓

Start SwingWorker

↓

Split into Chunks

↓

Generate Embeddings

↓

Update PostgreSQL

↓

Update Stored Hash

↓

Display "Indexed Successfully"

↓

Yes

↓

pendingIndex = true
```

If the hash is unchanged, no further work happens at all. If the hash has changed and no indexing worker is currently running, a new `SwingWorker` is started immediately. If a worker is already running, the save simply sets a `pendingIndex` flag instead of starting a second worker or queuing anything.

---

# 8.1 Repeated Save Handling

Users frequently press Ctrl + S multiple times in quick succession while still typing (for example while a note evolves from `a` → `ab` → `abc` → `abcd`). DeepNote does not need a queue to handle this correctly.

```
Ctrl + S

↓

Worker Busy?

↓

No

↓

Start Worker

↓

Yes

↓

pendingIndex = true

↓

Worker Finishes

↓

pendingIndex?

↓

Yes

↓

Run Again

↓

Latest Version Indexed
```

Behaviour:

- If no worker is currently indexing, a save immediately launches a new `SwingWorker`.
- If a worker is already indexing, the save does not start a second worker. It only sets `pendingIndex = true`.
- When the running worker finishes, it checks `pendingIndex`. If true, it clears the flag and starts indexing again using the latest saved content.
- This guarantees the database always converges on the most recently saved version of the note, without ever running more than one indexing worker at a time and without any queue, retry counter, or polling mechanism.

This is intentionally simple: at most one worker runs at a time, and at most one more indexing pass is ever "owed" after it finishes.

# 10. Search Ranking

DeepNote ranks notes rather than individual chunks.

The ranking algorithm:

- Uses the highest-scoring chunk as the primary score.
- Adds a small contribution from the second and third highest matching chunks.
- Filters low-quality matches using a configurable similarity threshold.

This produces more meaningful search results while avoiding duplicate entries.

---

# 11. Hash-Based Change Detection

Each note stores the SHA-256 hash of the content that was last indexed.

Workflow:

```
Save Note

↓

Compute Current Hash

↓

Compare with Stored Hash

↓

Same

↓

Skip Indexing

↓

Different

↓

Re-index Note
```

This prevents unnecessary embedding generation.

---

# 12. Chunking Strategy

DeepNote uses LangChain4j's Recursive Document Splitter.

Configuration:

- Target chunk size: 512 tokens
- Overlap: 64 tokens
- Tokenizer: EmbeddingGemmaTokenizer

The splitter attempts to preserve paragraphs while ensuring token limits are respected.

---

# 13. Embedding Generation

Embeddings are generated locally using:

- Ollama
- EmbeddingGemma
- LangChain4j

Large notes are embedded in batches to reduce memory usage.

---

# 14. Database Interaction

PostgreSQL stores:

- Note metadata
- Categories
- Chunk information
- Vector embeddings

TXT files store the actual note contents.

---

# 15. Threading Model

DeepNote performs semantic indexing using SwingWorker.

Main Thread (EDT):

- User interface
- Editing
- Button events

Background Thread (SwingWorker):

- Chunk generation
- Embedding generation
- Database updates

This prevents long-running AI operations from freezing the GUI.

---

# 16. Error Handling

If semantic indexing fails:

- The failure is wrapped inside a `NoteIndexingException`.
- The TXT file remains saved.
- Existing vectors remain unchanged.
- The user is notified.
- Keyword search continues to work.

If Ollama is unavailable, semantic search is temporarily disabled while keyword search remains available.
